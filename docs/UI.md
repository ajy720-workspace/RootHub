## 1. MVP 핵심 화면 리스트 구성안

MVP 단계에서는 다음 3가지 핵심 화면(또는 뷰)으로 유저 시나리오를 완벽히 커버할 수 있습니다.

### ① 메인 검색 및 검색 결과 화면 (The Anatomy Lab)

유저가 가장 먼저 마주하며, 서비스의 핵심 가치 제안(Core Value)이 실현되는 **가장 중요한 메인 화면**입니다. PRD 3.2의 레이아웃 요구사항을 충족합니다.

* **주요 UI 컴포넌트:**
* **상단:** 브랜드 로고, 검색바, 최근 검색어 칩(Chips)
* **중앙 (Visual Breakdown):** 유동적 시퀀스 기반의 형태소 블록 (컬러 코딩 적용)
    * 형태소 블록 클릭 시, 하단 Drawer가 올라오며 해당 형태소(re-, -fine- 등)의 라틴어/그리스어 기원, 본래 의미를 설명하는 뷰를 제공. 형태소를 북마크(저장) 버튼 포함
* *Prefix (파랑), Root (빨강/Bold), Suffix (초록)*

* **중하단 (Insight Section):** 각 형태소 블록의 상세 의미(기원, 역할) 및 AI가 생성한 '어원 스토리 카드'
* **하단 (Related Words):** 동일 어근을 공유하는 '가족 단어(Word Family Tree)' 횡스크롤 카드 영역 + 각 카드 내 북마크(저장) 버튼



### ② 나만의 단어장 화면 (My Library)

유저가 학습한 단어와 어원을 저장하고 복습함으로써 서비스의 리텐션(재방문율)을 높이는 화면입니다.

* **주요 UI 컴포넌트:**
* **상단 탭 전환:** '단어 모아보기' vs '어근/접사 모아보기' (PRD 2.4 요구사항)
* **단어 탭 리스트:** 유저가 저장한 전체 단어 리스트 (클릭 시 메인 랩 화면의 해당 단어 결과로 이동)
* **어근/접사 탭 리스트:** 저장된 형태소 원형과 의미 리스트 (어근 중심 학습용)
* **필터/정렬:** 최신순, 알파벳순 정렬 및 검색바



### ③ 로그인 / 회원가입 화면 (Auth)

Auth.js를 활용하여 최소한의 유저 식별 및 단어장(user_collections) 연동을 위해 필요한 화면입니다.

* **주요 UI 컴포넌트:**
* 소셜 로그인 버튼 (Google 등) 또는 이메일 간편 로그인
* *MVP 팁: 초기 검증 시 이 화면을 건너뛰고 LocalStorage를 활용해 단어장을 임시 저장하게 하면 전환율을 더 높일 수 있습니다.*

## 2. 유저 여정(User Journey)별 화면 흐름

```
[로그인 화면] 
      ↓ (진입)
[메인 화면: 비어있는 검색바] 
      ↓ (단어 검색 실행: DB 조회 또는 AI Prompt 호출)
[메인 화면: 블록 렌더링 + 스토리 출력] 
      ↓ (특정 어근 블록 클릭 / 하단 연관 단어 저장 버튼 클릭)
[나만의 단어장 화면] (학습 및 복습)

```

## 3. MVP 개발을 위한 UI/UX 구현 핵심 가이드

* **인터랙션 피드백:** PRD 3.2에 명시된 '조립되는 느낌의 Slide-up 애니메이션'은 유저에게 단어가 구조적으로 결합한다는 인상을 주는 핵심 재미 요소(Aha-moment)이므로 MVP 단계에서도 프론트엔드(Tailwind + Framer Motion 등)로 구현하는 것을 적극 추천합니다.
* **유동적 시퀀스 대응:** 고정 3단(접두-어근-접미)이 아니므로, Next.js 컴포넌트 렌더링 시 `word_segments` 테이블의 `sequence` 값에 따라 개수 제한 없이 가로로 나열되도록 `flex-wrap`을 필히 적용해야 합니다.

이 정도의 화면 리스트로 시작하신다면 Next.js + PostgreSQL + Gemini 스택으로 2~3주 내에 핵심 가치 검증이 가능한 완성도 높은 MVP를 빌드하실 수 있습니다.
